# Skills Manager

Skills Manager is the context for maintaining reusable AI agent skills and deciding where those skills are available. It distinguishes the user's central collection of skills from the agent and workspace locations where skills are applied.

## Language

**Skill**:
A reusable capability package that an AI agent can discover and use.
_Avoid_: Plugin, extension

**Skill Library**:
The user's central collection of managed skills. A skill can belong to the library without being available to any agent.
_Avoid_: Store, marketplace, global folder

**Skill Source**:
The place a skill was imported from or can be refreshed from, such as a local folder, Git repository, archive, or skill marketplace.
_Avoid_: Origin

**Tool**:
A configured AI coding agent target whose skills folder can receive managed skills. When user-facing text says "agent", it refers to the same target.
_Avoid_: Integration

**Preset**:
A named reusable group of skills and MCP servers that can be applied to a workspace or set of tools.
_Avoid_: Scenario

**Global Workspace**:
The per-tool skills area outside any single project. It exists because a Tool has a global skills location; it is not a user-registered workspace.
_Avoid_: Library, central repository

**Project Workspace**:
A project-local skills area that applies only within one project. It is a user-registered workspace.
_Avoid_: Global workspace

**Linked Workspace**:
An external skills root managed as its own workspace rather than as a project-local or global workspace. It is a user-registered workspace.
_Avoid_: Project workspace

**Install**:
The act of adding a skill to the Skill Library from a Skill Source. Installing a skill does not necessarily make it available to any tool.
_Avoid_: Sync

**Sync**:
The act of making library skills or MCP servers available to tools or workspaces. Sync-managed Tool targets are distinct from ordinary Skill copies that live in a Project Workspace or Linked Workspace.
_Avoid_: Install

**Adopt**:
The act of bringing a skill that already exists in a tool's skills folder under Skill Library management.
_Avoid_: Install, sync

**MCP Server**:
A single MCP tool configuration consisting of a command, arguments, environment variables, and startup options. Stored as a `.toml` file in the MCP Library. Each file contains exactly one `[mcp_servers.<name>]` section; the server name is the unique identifier.
_Avoid_: Plugin, integration

**MCP Library**:
The user's central collection of MCP Server configurations, located at `~/.skills-manager/mcp/`. Parallels the Skill Library but for MCP servers instead of skills.
_Avoid_: MCP store

**MCP Profile**:
A per-preset output file (`{preset}.config.toml`) generated by merging all MCP Servers in a preset. Placed in a tool's MCP Output Directory and loaded by the tool via its profile mechanism (e.g., `codex --profile {preset}`).
_Avoid_: MCP config bundle

**MCP Output Directory**:
A per-tool directory where the MCP Profile file is written. Defaults to the parent of the tool's `relative_skills_dir` (`.codex/skills` → `.codex/`), overridable in settings.
_Avoid_: MCP target, MCP sync root

**MCP Output Format**:
A per-tool setting specifying the serialization format of the MCP Profile file. Defaults to `toml` for all tools. Codex uses TOML (loaded via `--profile`); future tools may use JSON (`"mcpServers": {...}`). The central library stores all MCP Servers in TOML regardless; format conversion happens only at sync time.
_Avoid_: MCP format, profile format
